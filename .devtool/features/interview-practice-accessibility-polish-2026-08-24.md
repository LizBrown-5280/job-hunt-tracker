# Interview Practice: Accessibility & Polish

Ensure the interview practice feature is accessible and polished across all devices.

## Acceptance Criteria

- [ ] Test keyboard navigation: Tab, Arrow keys, Enter, Escape (all work as expected)
- [ ] Run axe/WAVE accessibility audit (no critical issues)
- [ ] Test with screen reader (NVDA, JAWS, VoiceOver)
- [ ] Ensure color contrast meets WCAG AA (4.5:1 for text)
- [ ] Add ARIA labels and roles where needed
- [ ] Test on mobile (iOS Safari, Android Chrome)
- [ ] Test on tablet (iPad in both orientations)
- [ ] Ensure full-screen mode works (F11, browser fullscreen)
- [ ] Add loading states and error handling
- [ ] Validate form inputs (e.g., max response length)
- [ ] Test performance: load time, memory usage with many questions

## Notes

Accessibility is not optional. Keyboard users and screen reader users should have a great experience. Polish includes error messages, loading indicators, and edge case handling.
